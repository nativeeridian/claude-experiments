Analytics operating model · demonstration

Snowflake decides the number. The model decides the story.

Anyone asks in plain language. Metric definitions stay where they already are — in the warehouse, in SQL, under change control. The model picks the right one, fills an approved template, and delivers a finished artifact in minutes instead of days.

The division of labor

This is the whole idea. Once leadership agrees to this split, the rest is procurement and plumbing.

Snowflake & SQLDeterministic

Owns every number. Same question, same answer, every time — and the same answer your finance close produces.

  • What “gross margin” means
  • Which tables join to which
  • How the number is aggregated
  • Which rows each person may see

Changing any of these is a reviewed, versioned code change — exactly as it is today. The model cannot alter them.

The modelJudgment

Owns the interpretation. Every choice it makes is printed on the artifact, so it can be challenged by anyone reading it.

  • Which metric answers this question
  • Which template fits — or what to build when none does
  • What the movement means for the business
  • What to recommend, and to whom

Wrong judgment is visible and arguable. Wrong arithmetic is not possible — it never touches the arithmetic.

Neither one is ever allowed to invent a number. If the metric isn't defined, the answer is “I can't compute that yet” — never a plausible guess.

What it looks like in practice

Three requests a business user could make today. Same machinery each time; the output changes because the question does.

Self-service, for real. No ticket, no queue, no analyst. Type a request and watch the same four steps run.
