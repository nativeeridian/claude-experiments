The model

Five layers and two spines. The products change by organization size; the layers don't. Trace steps below are tagged by the layer they run in.

L5DeliveryProduces a finished artifact from a reviewed template — not a chat reply.answer card · brief · report · watch
L4ReasoningPlans the work, picks the lane, knows when to stop and refuse.agent host + Skills (method) + lane router
L3MeaningDefines what the numbers mean. The query is compiled here, not written by the model.dbt Semantic Layer · Cube · semantic views — Apache Ossie aligned
L2AccessOne governed door per system, opened as the person asking.MCP servers · OAuth 2.1 · least privilege
L1SourcesThe warehouse, the operational systems, and the spreadsheets and PDFs nobody modeled.Snowflake · Salesforce · Zendesk · DuckDB over files · document index
Trust20 golden questions with human-verified answers, run like a test suite. Provenance rendered on every artifact.
ControlLeast privilege, no token passthrough, retrieved content treated as data and never as instructions, full audit trace.

The model never defines a metric

It picks from definitions the business already agreed, and a compiler writes the SQL. It cannot invent a wrong join or a wrong aggregation.

98–100% vs 84–90% on benchmark
Refusal is a shipped feature

Free text-to-SQL fails silently — a confident wrong number in a board deck. A governed layer fails loudly and names what modeling it would take.

see question 5
The off-schema half is in scope

The rebate spreadsheet and the carrier notice carry most of the margin story. They're read, cited by version, and labeled un-certified — never silently merged with governed numbers.

governed · referenced · quarantined
The output is a document

Nobody wants a query result; they want the bridge with three recommendations. Templates fix the sections, the allowed metrics, and the non-removable provenance block — reviewed once, reused forever.

3 templates, 1 answer card

Ninety days to a first domain

One domain, one sponsor, twenty questions. The expensive input is definitional agreement, not compute.

Weeks 1–2Agree the questions

Collect the 20 questions leadership actually asks. Write the correct answers by hand. This is the scope document and the test suite at once.

Weeks 3–8Define the meaning

Model 15–30 metrics — not the warehouse. Name one owner per definition. Identify which answers need off-schema files.

Weeks 5–8Open the doors

MCP access to the warehouse, one operational system, and the file store. Identity and least-privilege review before anyone connects.

Weeks 7–10Teach the method

Write 3–5 Skills encoding how your analysts actually work. Build three artifact templates and get them reviewed once.

Weeks 9–13Prove it, then land it

Run the golden set to 100% in-scope and 100% correct refusal. Then 20–30 pilot users — with training as a budget line, not an afterthought.
